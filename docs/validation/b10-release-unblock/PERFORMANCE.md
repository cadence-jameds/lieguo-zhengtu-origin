# 原生容量、效能與記憶體

環境：Chromium 154.0.8037.57／Linux／2 CPU quota／8 GiB，Node 22.23.4。正式 Persistence 路徑使用原生 IndexedDB；不是 Node／fake-indexeddb。舊版完整 PR #60 `aaaee9d`；新版 Persistence `72e0e45`（內容 `3a3ae8d`），GameApp `243f68a`／0.31.18。後者只包含一項已撤回的 SW 實驗，src bytes 與 `3a3ae8d` 完全相同；沒有遊戲／Persistence 邏輯差異。原始摘要及 checksum 見 `measurements.json`。

Fixture：相同 seed 的合法 100 勢力、99 個已排程 AI、25X，使用不同累積 rolled-back 改名歷史而保持等價最終世界；0～60k 的初始城市／事件／seed／time digest 舊新版逐組相等，完整玩法另有 31 世界對照。這是正式儲存量測，不是 150k 次真實命令吞吐或活躍 99 AI 競爭；後者另測真正 GameApp 十分鐘。

暖操作 n=20；reopen、每種匯出／匯入、Recovery 各 n=5；冷載入另用 5 個全新 Worker。nearest-rank p50／p95，n=5 的 p95 是樣本最大值。依序執行，沒有本機 CPU 重型工作並行；保留 OS／GC 雜訊。以下所有時間 ms，未用不同環境的 R3-03／04 舊秒數計算精確比例。

## 獨立記憶體／GC 診斷

相同 150k fixture、2 warm／1 heavy、原生實際路徑；**不是**舊版失敗 n20／5 的替代 PASS。250ms heap、1 秒 RSS 抽樣，無 forced GC。舊版 Worker used 峰值樣本 **1,361,473,904 bytes**，新版 **223,774,568 bytes**；backing **737,588,455→59,853,344 bytes**。最大 renderer RSS **2,958,392→530,200 KiB**；browser tree sum **3,638,244→1,043,280 KiB**，shared pages 會重複，不是 PSS，也不是瞬時峰值上界。

舊診斷觀察 MinorGC 120 個／900.611ms、MajorGC 3 個／106.397ms；GC subphase 可重疊，不加總當互斥 pause。新版短診斷視窗沒有觀察到匹配 GC event，**不等於零 GC**。fixture 在 Worker 先建立原始 150k 工程輸入的配置也在抽樣內；正常新版冷載入不會先建立那份歷史。

Soak 的真實 AI 決策、稀疏玩家命令、T1 延遲與長任務另記總報告；不能拿本表 20 次單路徑暖操作當成 AI 競爭實測。
