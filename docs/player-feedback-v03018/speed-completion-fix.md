# v0.30.18｜高倍速短工程到期修正

日期：2026-10-06（台灣時間）。B4 Player Feedback 的額外阻塞修正；B5 尚未開始。

## 原因

Worker 的世界時間使用 `實際經過時間 × world.speed`，倍率公式正確。然而前景只每 10,000ms 執行一次 `advanceAndSave`，短工程直到下一個 tick 且持久化成功才呈現完成。因此 50X 預覽約兩秒的工程可能等近十秒才顯示結果。建造視窗已使用現實時間，佇列等處卻仍使用世界時／分，造成另一層顯示不一致。

## 修正

- Worker 每 100ms 檢查；一般狀態每秒推進，當正式事件到期時不等待整秒週期，立即進入原序列化提交流程。
- 全部時間仍依絕對 performance anchor 計算，持久化花費時間不會被丟掉；已有 tick 待處理時合併後續輪詢。
- 成功持久化後才發布狀態；提交失敗保留既有世界，至少隔一秒重試，避免密集失敗循環。
- 共用 `realTime`，施工預覽、工程／訓練佇列、科研及行軍剩餘時間採倍率換算後的現實時分秒。排隊耗時保留。
- 不改 Formal 工期、成本、事件順序、存檔格式與 v85 規則。

## 驗證

Formal 核心／Presentation／存檔鎖 28 檔、264 項通過；TypeScript 與 Vite/PWA build 通過。Worker 回歸使用實際 Formal 建設命令與事件處理，在 1／3／6／10／50X 比較到期前與到期後。50X 林地升級預覽取整為兩秒，按實際毫秒到期完成；不等待十秒 tick。另驗證慢提交期間沒有重複保存、完成前不發布 draft，後續時間可追上絕對時鐘。

100ms 是前景輪詢間隔，並非每 100ms 存檔。顯示完成仍需加上裝置的提交及畫面更新耗時；背景分頁限流、手機實機 FPS／IndexedDB 延遲未實測，不承諾零延遲。
