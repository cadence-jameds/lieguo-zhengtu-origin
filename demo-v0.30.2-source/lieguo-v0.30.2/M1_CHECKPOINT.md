# M1 Checkpoint — 確定性世界與可靠存檔

## 完成狀態

M1 已把 M0 的展示型持續世界提升成可安全承接後續城市、軍隊與 AI 系統的基礎。重點不是增加大量表面功能，而是確保相同 seed、命令與時間一定產生相同結果，而且存檔損毀、背景休眠或誤開多分頁時不會靜默破壞戰役。

### 世界與地圖

- 世界模擬仍在 Web Worker 中持續運行，畫面執行緒只讀取 WorldView 並送出命令。
- 地圖維持 2:1 等距菱形棋盤；草地、農田、森林、山地、水域、河流、道路與據點均在同一投影上。
- 可玩格線外另鋪無格線地形並使用同色地表底層，因此矩形視窗四角與邊界看起來仍屬於完整世界。
- M1 仍是 28 × 22 格的區域展示；正式 256 × 256 世界與分區載入尚未假裝完成。

### 確定性命令與事件

- 所有玩家操作使用版本化 `WorldCommand` 進入權威模擬。
- 接受與拒絕的命令皆留下序號化 command log。
- 排程事件依 `dueWorldTimeMs → priority → sequenceId → id` 穩定排序。
- 同一毫秒到期的所有事件會完整結算，不會因剩餘時間歸零而漏掉後續事件。
- RNG 已拆為 simulation、map、AI、combat 四條狀態，避免新增一個系統後改變其他系統的隨機結果。

### 存檔與回復

- IndexedDB Schema 2 包含 campaigns、snapshots、eventQueue、commandLog、backups、settings 與 contentMeta。
- Snapshot、事件佇列、命令紀錄與內容版本在同一 Dexie transaction 中提交。
- 每個戰役最多保留 5 份輪替備份；有效快照依保存時間與 revision 選取。
- Snapshot checksum 涵蓋確定性世界 hash、revision 與最後提交時間；物件鍵順序不影響結果。
- 當最新快照或獨立事件佇列未通過檢查時，會回復最近的有效備份；若全部損毀則停止載入且不覆寫原資料。
- 舊 M0 Schema v1 會明確遷移至 v2，包括事件與斥候任務關聯及四條 RNG 狀態。

### 可攜式存檔

- 玩家可匯出人類可攜的 `.realm-save` JSON 檔。
- 匯入檔上限為 5 MiB，先在記憶體中驗證格式、schema、checksum、事件佇列、RNG 與戰役中繼資料。
- 驗證全部通過後才會覆蓋目前戰役，且覆蓋前先建立回復點。
- 匯入需要介面中的明確確認，不接受靜默覆蓋。

### 執行生命週期

- Web Locks 確保同一瀏覽器同一戰役只有一個寫入分頁；其他分頁停在保護畫面。
- BroadcastChannel 公告寫入者狀態，Web Lock 仍是實際互斥依據。
- 分頁隱藏與 pagehide 會要求 Worker 提交快照；回到前景會立即續算。
- 活躍分頁以 wall clock 承接裝置休眠，以 monotonic clock 防止裝置時間倒退造成負推進。
- 時鐘倒退不產生負離線收益；三日以上跳躍會留下系統診斷但仍按相同規則追算。
- Master 規定的新手保護已校正為標準模式 72 小時。

## 驗證基準

- 型別檢查：`npm run typecheck`
- 全部單元測試：`npm run test`
- 48 小時無頭模擬：`npm run simulate:48h`
- 正式建置：`npm run build`
- GitHub Pages 子路徑建置：設定 `GITHUB_ACTIONS=true` 與 `GITHUB_REPOSITORY=owner/repository` 後執行建置

涵蓋的關鍵測試包括：

- 一次推進與分段推進的世界 hash 相同。
- 同時到期事件依固定規則全部結算。
- 在線分段與離線一次追算得到相同斥候結果。
- 48 小時一次追算與 288 個十分鐘切片完全一致。
- M0 v1 存檔可遷移至 M1 v2。
- 損毀的最新快照會被略過並選擇有效備份。
- 可攜式存檔可往返，竄改內容會在覆蓋前被拒絕。
- 時鐘倒退不增加負時間，長時間跳躍會被標記。
